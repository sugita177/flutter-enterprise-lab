### 2026-11-25 | Phase 1: 変数宣言・型推論・コレクション操作

- **学んだ核心:**
  - `final`（実行時定数）と `const`（コンパイル時定数）の違いを理解し、実行時に決まる値には `final`、固定値には `const` を使い分けた。
  - `List` / `Set` / `Map` の基本操作に加え、コレクションリテラル内で直接 `if` / `for` を使ってリストやマップを構築する構文を実践した。
  - `flutter_lints` の `avoid_print` ルールにより、本番コードでの `print` 禁止（ログ漏洩・性能低下防止）の意図を学んだ。
- **ハマったポイント・疑問点:**
  - `Map` の初期化では `Map.fromIterable` よりもコレクション `for` の方が型安全に書ける。
  - 既存の `TODO:` コメントに Dart Analysis Server が青い波線（Info）を出す仕様を確認した。
- **設計上の気づき・他言語との対比:**
  - `List` から重複排除した `Set` を作るときは `Set.from()` より `toSet()` の方が型安全。
  - `Map.update(..., ifAbsent: ...)` を使うと「既存キーの更新」と「新規キーの追加」を安全かつ簡潔に表現できる。

### 2026-11-26 | Phase 1: Null Safety と型昇格

- **学んだ核心（自分の言葉での要約）:**
  - `?.` と `??` を組み合わせることで、`null` が混入してもクラッシュせずに安全なデフォルト値へフォールバックできる。
  - 早期リターン（ガード節）で `null` チェックを行うと、以降のスコープで自動的に非 Null 型へ型昇格（Type Promotion）する。
  - `late final` は初期化前にアクセスすると実行時エラー（`LateInitializationError`）になるため、乱用を避けるべき。
- **ハマったポイント・疑問点:**
  - 空白のみの文字列 `'   '` は `null` ではないため `?.` を通過し、`trim()` 後に空文字として出力される。業務では `null` だけでなく `trim().isEmpty` も合わせてガードする必要がある。
- **設計上の気づき・他言語との対比:**
  - `!`（Null アサーション）は現場端末でのクラッシュ原因になるため原則禁止とし、ガード節や `??` で安全に処理する。
